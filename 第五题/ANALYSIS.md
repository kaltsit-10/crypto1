# 第五题分析与三种求解方案

## 问题参数

| 参数 | 值 |
|------|-----|
| n = m = q | 120 |
| γ（ℓ∞ 上界） | 16 |
| t 向量 | 全零（齐次 SIS） |
| **额外约束** | **‖u‖₂² + ‖v‖₂² ≥ q² = 14400**（即组合 ℓ₂ ≥ 120） |

**目标**：找 (u, v) ∈ ℤ^120 × ℤ^120，满足：
1. A·v + u ≡ 0 (mod 120)
2. ℓ∞(u, v) ≤ 16
3. **ℓ₂(u, v) ≥ 120**（与第三题唯一区别）

---

## 核心数学分析

### 格的 GH 估计

SIS 格维度 = 240，行列式 = 120^120。

```
GH(240) ≈ √(240/(2πe)) × √120 ≈ 41.1
```

- 标准筛法（BKZ/Sieve）找到的最短格向量：ℓ₂ ≈ 41
- 我们需要的目标向量：ℓ₂ ≥ 120 ≈ 2.9 × GH
- **结论：标准筛法找到的最短格向量全部不满足条件！**

### P3 解与 P5 条件的差距

P3 的解（ℓ∞ = 16，∼446秒求得）：
- ℓ₂² = 12002，ℓ₂ = 109.6
- 距离 P5 条件差：14400 - 12002 = **2398**
- P3 的解是"稀疏"的：14个零元，98个绝对值 ≤ 4 的元素

### 格内满足条件的解有多少？

格点 (u,v) 均匀分布在 [-16,16]^240 中的数量估计：
```
32^240 / 120^120 ≈ 2^(240×5) / 2^(120×6.9) ≈ 2^371 个 SIS 解
```

"典型"解的 ℓ₂：√(240 × 256/3) ≈ 143 >> 120

**绝大多数 SIS 解天然满足 ℓ₂ ≥ 120，只有最短的少数解不满足！**

问题转化为：**如何找到一个"非最短"的 SIS 解**（而标准格算法专门找最短的）。

### 条件概率

对于 ℓ₂ = R 的向量，满足 ℓ∞ ≤ 16 的概率：
```
P(ℓ∞ ≤ 16 | ℓ₂ ≈ R, dim=240) = Φ(16√240/R)^240 - ...
```

| R（目标 ℓ₂） | P(ℓ∞ ≤ 16) | 期望需要尝试次数 |
|--------------|------------|----------------|
| 41 (GH)      | ≈ 1.0      | 1              |
| 120          | 7.4×10⁻⁵   | ~13,600        |
| 130          | 8.5×10⁻⁷   | ~1,170,000     |
| 143 (均匀)    | ≈ 3×10⁻⁸   | ~30,000,000    |

→ **ℓ₂ 略超过 120 是最易满足 ℓ∞ 条件的点**，不要追求大 ℓ₂。

## 方案一：BKZ-60 预约化 + 并行随机基向量组合搜索

### 核心思想

BKZ-60 约化后，格基前几行有 ℓ₂ ≈ 120-159，**已经在目标 ℓ₂ 范围内**。
对这些格基行做小系数整数组合，随机搜索满足 ℓ∞ ≤ 16 的组合。

### 方法步骤

**第一阶段：BKZ-60 约化（~15-30 分钟）**

```python
# 构造 240×240 SIS 格基
# 前120行: (q*e_i || A_row_i)  → 这些行是 ℓ₂ ≈ √(q² + ||A_row||²) ≈ 765 的大向量
# 后120行: (0 || -e_j)         → ℓ₂ = 1 的单位向量

# 运行 BKZ-60（用 fpylll，约化到 δ ≈ 1.0113）
from fpylll import IntegerMatrix, LLL, BKZ
B = IntegerMatrix(240, 240)
# ... 填充 SIS 格基 ...
LLL.reduction(B)
BKZ.reduction(B, BKZ.Param(60))
# → 前几行 ℓ₂ ≈ 159，格基前20行均在 [100, 200] 范围
```

**第二阶段：190核并行随机组合搜索**

```python
# 每个 worker 独立运行：
# 取前 K=15 个 BKZ-60 格基行
# 对每个随机系数向量 c ∈ {-2,-1,0,1,2}^K：
#   x = Σ c_i * B[i]
#   if ℓ∞(x) ≤ 16 and ℓ₂(x) ≥ 120: DONE

# 搜索空间: 5^15 ≈ 3×10^10 → 190核分担 ≈ 1.6×10^8/核
# 向量化计算: NumPy 批处理 10000 个组合/次
# 总时间估计: 3×10^10 / (190 × 10^6 次/秒) ≈ 160 秒
```

### 参数估计

- BKZ-60 后第1个格基行 ℓ₂ ≈ 159 > 120 ✓
- P(ℓ∞ ≤ 16 | ℓ₂ = 130) ≈ 8.5×10⁻⁷
- 期望需要约 130 万次尝试
- 5^15 ≈ 300 亿次搜索 >> 130 万，**高度可信会找到解**
- 190核总计算时间：**~2-10 分钟**

### 关键注意事项

- BKZ-60 比 P3 的 BKZ-95 快得多（块大小小一半以上）
- 不需要 G6K，纯 fpylll 即可
- 每次尝试只需一次矩阵-向量乘（NumPy 批处理极快）
- 格基行本身就是有效 SIS 格点，组合后仍满足 A·v + u ≡ 0 (mod q)

## 方案二：G6K 筛法 + 中长度向量过滤

### 核心思想

G6K 筛法维护一个**数据库**，内含约 2^(0.2075×β) 个向量。
标准用法只取最短向量；**本方法在每步筛后扫描全数据库**，检查是否有
ℓ₂ ≥ 120 AND ℓ∞ ≤ 16 的向量（这类向量在筛法早期迭代时仍存在）。

### 方法步骤

```python
# 基于 P3 的代码框架，做如下修改：

# 修改1: 在每次 pump 调用后，扫描 G6K 的向量数据库
def check_medium_vectors(g6k, gamma=16, q=120):
    """扫描 sieve 数据库中的中长度向量"""
    for i in range(g6k.n):
        x = g6k[i]  # 获取第 i 个数据库向量（在格基坐标下）
        # 转换到原始坐标
        vec = reconstruct_vector(x, basis)
        l_inf = max(abs(v) for v in vec)
        l2_sq = sum(v*v for v in vec)
        if l_inf <= gamma and l2_sq >= q*q:
            return vec
    return None

# 修改2: 在筛法的"早期"阶段（前几轮迭代）重点检查
# 因为：筛法收敛时向量变短（排除），在收敛前存在中长度向量

# 修改3: 使用较低 β（β=80 而非 P3 的 β=105）
# β=80 时，筛法只将向量压缩到 ℓ₂ ≈ 122（BKZ-80 估计），
# 恰好在目标范围 [120, 248] 内！
```

### BKZ-80 的特殊性质

从 BKZ RHF 估计（δ_80 ≈ 1.0101）：
```
BKZ-80 首向量范数 ≈ 1.0101^239 × √120 ≈ 121.9 ≈ q
```

**这意味着：BKZ-80 约化后第一个格基行的 ℓ₂ ≈ 120，恰好满足下界条件！**

此时只需要该向量的 ℓ∞ ≤ 16（概率 ≈ 1/13600），而 G6K 在 BKZ-80 框架下
会生成约 2^(0.2075×80) ≈ 2^16.6 ≈ 100,000 个这样的候选向量。

```
期望成功次数 = 100,000 / 13,600 ≈ 7 次 ✓
```

### 实现策略

```python
# 40 个 worker × 8 线程（与 P3 相同并行架构）
# 每个 worker: pump(kappa=0, beta=80, dim4free=5.5)
# 在每次 pump 后：
#   1. 扫描全数据库（100,000 向量）
#   2. 检查 ℓ∞ ≤ 16 AND ℓ₂ ≥ 120
# 
# 40 个并行 worker 合计约 4,000,000 次检查 / pump 轮
# 期望找到解：在最初几个 beta 级别就能命中
```

### 时间估计

- BKZ-80 比 BKZ-105 快 3-5 倍
- **预计 30-90 分钟**

## 方案三：P3 解后处理 + 格内"提升"搜索

### 核心思想

P3 已给出一个 ℓ∞ ≤ 16 的解 x₀（ℓ₂² = 12002，差 2398）。
在同一 SIS 余子集 x₀ + L 中搜索 ℓ₂ 更大的点。

### 关键观察

设 x₀ = (v₀, u₀) 是已知 SIS 解。任意 SIS 解都形如 x₀ + Δ，
其中 Δ 是 SIS 格 L 的格点（即 Δ 满足 A·Δᵥ + Δᵤ ≡ 0 mod q）。

我们想找 Δ ∈ L，使得：
- ℓ∞(x₀ + Δ) ≤ 16 → 各坐标：-16 ≤ x₀[i] + Δ[i] ≤ 16
- ℓ₂(x₀ + Δ)² ≥ 14400

**核心约束转化**：
对每个坐标 i，Δ[i] ∈ [-16 - x₀[i], 16 - x₀[i]]（宽度最小为 0，最大为 32）

若 x₀[i] = 0，则 Δ[i] ∈ [-16, 16]（宽度 32）
若 |x₀[i]| = 16，则 Δ[i] = 0（完全固定）
若 |x₀[i]| = 1，则 Δ[i] ∈ {-17..15} 或 {-15..17} → 约束非常宽松

### 方法步骤

**步骤1：运行修改版 P3 代码，找到多个（>50个）ℓ∞ ≤ 15 的解**

```python
# 修改 P3 的 parallel_pump.py：
# - 降低停止门槛从 ℓ∞ ≤ 16 到 ℓ∞ ≤ 15（留出 1 的裕量）
# - 收集所有找到的解，不仅仅是第一个
# - 检查每个解的 ℓ₂ 是否已满足 P5 条件
```

**步骤2：对找到的解直接检验**

```python
for sol in collected_solutions:
    l2_sq = np.sum(sol**2)
    if l2_sq >= 14400 and np.max(np.abs(sol)) <= 16:
        return sol  # 直接满足！
```

**步骤3（备用）：两解组合**

若已有 x₀（ℓ∞ ≤ 14）和 x₁（ℓ∞ ≤ 14），且 x₀, x₁ 满足 A·v + u ≡ 0：
- x₀ + x₁ 也是有效解（格点加法）
- ℓ∞(x₀ + x₁) ≤ ℓ∞(x₀) + ℓ∞(x₁) ≤ 14 + 14 = 28 → 可能超限

更精确地：逐坐标检查 |x₀[i] + x₁[i]| ≤ 16。
若 x₀ 和 x₁ 的符号结构"互补"（即 x₀[i] > 0 时 x₁[i] < 0），则各坐标绝对值不超限。

```python
# 搜索：在收集到的解集中找 (x₀, x₁) 对，使得
# - ℓ∞(x₀ + x₁) ≤ 16（坐标逐一检验）
# - ℓ₂(x₀ + x₁) ≥ 120
# 
# 若有 K 个解，搜索 K² 个对：K=1000 → 10^6 次检验，极快
```

### 为何 ℓ₂ 可能在多解中自然出现

P3 的筛法基于随机种子，每次运行输出的解具有不同的"能量分布"。
在大量解中，部分解的 ℓ₂ 天然 ≥ 120（P3 的解 ℓ₂ = 109.5 只差 10.4）。
理论上只需运行 P3 代码约 14 次（期望），即可找到 ℓ₂ ≥ 120 的解。

## 验证标准

解 `(v, u)` 各 120 维，验证：

```python
import numpy as np

def verify_p5(v, u, A, q=120, gamma=16):
    # 条件1: SIS 方程
    residual = (A @ v + u) % q
    assert np.all(residual == 0), f"SIS violated: max residual = {np.max(residual)}"
    # 条件2: 无穷范数
    linf = max(np.max(np.abs(v)), np.max(np.abs(u)))
    assert linf <= gamma, f"inf-norm violated: {linf} > {gamma}"
    # 条件3: 欧氏范数下界
    l2sq = np.sum(v**2) + np.sum(u**2)
    assert l2sq >= q**2, f"L2 condition violated: {l2sq} < {q**2}"
    print(f"✅ Valid! ℓ∞={linf}, ℓ₂={np.sqrt(l2sq):.2f}")
```
